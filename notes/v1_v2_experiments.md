# TPU-MJX Batch Renderer Experiments Log

> Follows `rtx-h100` experimental discipline (`gpu-profile`, `kernel-specialize`, `quality-gate`, `cache-bake`):
> 1. **Predict before measuring**; keep all negative results and root-cause attributions.
> 2. **End-to-end throughput only** (`MJX step + Render`), JIT-warmed, zero `host_callback` / zero CPU round-trips verified directly in XLA HLO.
> 3. **Immutable `gate.py`** thresholds locked in Phase 0 (zero post-hoc threshold relaxation).

---

## Phase 0: Hardware, Environments & Reference Setup

- **Live TPU Silicon**: Google Cloud TPU `v5p` (Google Cloud TPU v5p host, zone `us-east5-a`, 459 TFLOP/s BF16, 2.765 TB/s HBM, 95.74 GiB HBM, 64 MiB VMEM per chip, `I_ridge = 166 FLOP/B`) in single-host 1-chip (`TPU_VISIBLE_DEVICES=0`) and 4-chip (`0,1,2,3`) isolated configurations.
- **Software Versions**: `JAX 0.10.2`, `mujoco 4.0.1`, `mujoco-mjx 4.0.1`, Blender `5.2.0 LTS` (CPU Cycles `48 spp`, `max_bounces=6`). Isolated Python package overlay on the TPU VM.
- **Amdahl Profile Finding on Real `TPU v5p` (`PandaPickCube`, `B=1024, 64x64, 1 chip`)**:
  - `MJX step`: `12.39 ms` (`0.9%`)
  - `Stage 1 Analytic Raycast + Direct Shader (tiled=128)`: `~1242.6 ms` (`86.7%`, VPU/HBM-bound)
  - `Stage 2 M2_spatial_128 (24-ch BRDF, BF16 Conv)`: `~178.8 ms` (`12.5%` / `0.17 ms/frame` vs Stage 1 tiled `1242.6 ms`)
  - *Implication*: Stage 1 raycasting dominates `>86%` of total frame time, so optimizing Stage 1 VMEM working set (`tile_size` tiling) yields large speedups, while BF16 `M2_spatial_128` fits nearly for free on the MXU.
